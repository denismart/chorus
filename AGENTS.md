# Chorus: правила работы

## Версии ядра

- Каждая новая сборка с изменениями, которую передаём пользователю на проверку или устанавливаем на устройство, получает новый номер версии. После установки версии дальнейшие правки выпускаем с увеличенным patch-номером: например, после 0.4.2 — 0.4.3.
- Не переиспользовать номер уже переданной или установленной сборки для последующих изменений. Несколько связанных правок до первой передачи сборки могут входить в одну версию. Повторное копирование той же сборки без изменений не требует нового номера.
- Если пользователь явно указал номер следующей версии, использовать его.
- Перед обновлением сверять последние версии в CHANGELOG.md и установленном Chorus.toc. Согласованно обновлять CHANGELOG.md, упоминания планируемого выпуска в TODO.md и номер в установленном Chorus.toc.
- В исходном Chorus.toc сохранять `@project-version@`; настоящий номер подставлять при сборке или установке.
- Записи уже переданных версий в CHANGELOG.md сохранять; новые изменения записывать под новым заголовком.
- Публикация на GitHub и CurseForge — только по отдельному подтверждению пользователя.

## Проверка на Deck

- Пользователь проверяет изменения в игре сам. При копировании файлов не выполнять /reload и не управлять игрой без отдельной прямой просьбы.
